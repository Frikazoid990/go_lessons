# Lesson 3.1 — Copying Values

## Budget Preview

**Цель:** показать независимость копии `int`, локальность изменения параметра и явное сохранение возвращённого значения.

**Проект:** `go_lessons/block-03-values-pointers-structs/lesson-01-value-copy`; модуль `lesson-01-value-copy`.

**Вопросы до практики:**
1. После `a := 8; b := a; a = 13; b++` какие значения у `a` и `b` и почему?
2. Чем отличаются `calculate(budget)` и `budget = calculate(budget)`, если `calculate` принимает `int`, изменяет свой параметр и возвращает его?

**Задание:** написать одну программу Budget Preview в `main.go`.
1. В `main` создать `budget := 60`, сохранить его в `snapshot`, затем изменить `budget` на 45. Вывести обе переменные.
2. Объявить на уровне пакета `reserve(budget int, amount int) int`. Функция вычитает `amount` из своего параметра `budget`, выводит получившееся значение с меткой `inside` и возвращает его. Для этого урока входы корректны: `0 <= amount <= budget`; проверку отказа писать не требуется.
3. Вызвать `reserve(budget, 12)` без сохранения результата; затем вывести `budget` и `snapshot` с меткой `after ignored`.
4. Вызвать ту же функцию с теми же аргументами, сохранив результат в `proposed`. Вывести `budget`, `snapshot`, `proposed` с меткой `after preview`.
5. Присвоить `proposed` переменной `budget`, затем увеличить `proposed` на 1. Вывести три переменные с меткой `after commit`.
6. До первого запуска записать прогноз всех строк вывода в комментарии. После запуска сопоставить его с результатом; при расхождении оставить исходный прогноз и пояснить причину.

**Ограничения:** достаточно `int`, присваиваний, именованной функции и `fmt`. Без указателей, структур, коллекций, замыканий, глобального изменяемого состояния и тестов. Не заменять передачу параметра обращением к внешней переменной.

**Критерий:** код и объяснение показывают, какая именно переменная меняется на каждом шаге; копия сохраняет прежнее число, изменение параметра не заменяет `budget` в `main`, возвращённое значение влияет на него после явного присваивания. Прогноз сопоставлен с выводом.

**Что прислать:** ответы на два вопроса, код или сообщение о готовности файлов, прогноз и фактический вывод, 2–3 предложения о том, почему первый вызов не изменил `budget` в `main` и что изменило его позже.
