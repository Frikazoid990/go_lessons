### Lesson 3.3 — Delivery Counter

**Цель:** различить отсутствующий указатель и указатель на число 0, безопасно изменить число через параметр-указатель и обработать отсутствие адреса ранним возвратом.

**Проект:** `go_lessons/block-03-values-pointers-structs/lesson-03-nil-pointers`, модуль `lesson-03-nil-pointers`. Папка, `main.go` и `go.mod` уже созданы. Решение пишет пользователь.

**Порядок:** чтение и заметки → ответы → практика. Теория и примеры: [[📚Study📚/⌨️🖱️Programming/⌨️Backend/Go/Block Notes/📦 Block 03 — Values, Pointers and Structs#Lesson 3.3 — Nil Pointers and Safe Access|урок 3.3 в конспекте]].

**Вопросы до практики**

1. После `var p *int` и `count := 0` чем отличаются `p` и `&count`? Какие из выражений `p == nil`, `*p`, `*(&count)` можно вычислить безопасно и почему?
2. При `p == nil` чем отличается выполнение `p != nil && *p > 0` от `*p > 0 && p != nil`? Объясни порядок действий.

**Задание**

Программа учитывает поставку товара на склад. `stock` — число единиц товара на складе. `counter` — необязательный указатель на этот счётчик; `nil` означает, что счётчик не подключён. При отсутствии подключения поставка не учитывается: функция возвращает отказ и ничего не изменяет.

1. На уровне пакета объявить функцию с именем `recordDelivery`. Первый параметр `target` — указатель на `int`, адрес счётчика товара. Второй параметр `amount` — `int`, число единиц в поставке. Возвращаемое значение одно, типа `bool`: `false`, если `target` равен `nil`; `true`, если поставка учтена. При `nil` функция должна завершиться до обращения через указатель. Иначе она прибавляет `amount` к числу по адресу из `target` и возвращает `true`. Внутри функция ничего не печатает. Во всех вызовах задания `amount` положительный; проверка отрицательных чисел и переполнения не нужна.
2. В `main` объявить `stock` со значением 0 и `counter` типа указатель на `int` без начального адреса. Вызвать `recordDelivery`, передав `counter` и 5. Сохранить возвращённый результат и вывести первую строку ожидаемого вывода. `stock` остаётся 0.
3. Присвоить `counter` адрес именно переменной `stock`. Скопировать значение указателя из `counter` в новую переменную `observer`. Снова вызвать `recordDelivery` с `counter` и 5, сохранить результат и вывести вторую строку. Указатель на исходный 0 считается подключённым счётчиком; после вызова `stock` равен 5.
4. Присвоить `counter` значение `nil`. Вызвать `recordDelivery` с `counter` и 3, сохранить результат и вывести третью строку, прочитав последнее число через `observer`. После отказа `stock` остаётся 5, а `observer` продолжает указывать на `stock`.

**Ожидаемый вывод**

```text
Без счётчика: false; На складе: 0
С подключённым счётчиком: true; На складе: 5
После отключения: false; На складе: 5; Через наблюдателя: 5
```

Текст до значений — подписи вывода. Логические значения брать из результата функции, числа — из `stock` и, для последнего числа, через `observer`. Числа в выводе не подставлять готовыми литералами. Запуск — `go run .` из папки урока.

**Ограничения:** достаточно `int`, `*int`, `bool`, `nil`, присваиваний, `if`, `return`, именованной функции и `fmt`. Коллекции, структуры, `new`, обработка паники и автоматические тесты не нужны. Намеренно вызывать панику не требуется.

**Критерии:** все три случая проходят без паники; первый и третий вызовы возвращают `false` и не меняют `stock`; второй возвращает `true` и увеличивает исходный 0 до 5. Проверка `nil` предшествует записи через указатель. По объяснению видно, почему число 0 допустимо и почему отключение `counter` не изменяет `observer`.

**Что прислать:** ответы на два вопроса, путь к `main.go` или код, фактический вывод `go run .` и 2–3 предложения о том, почему второй вызов разрешён при исходном `stock == 0` и почему после отключения через `observer` читается 5.
