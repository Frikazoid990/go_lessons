# Lesson 2.10 — Order of Evaluation

## Calculation Trace

**Цель:** отличать группировку операций от порядка вызовов, замечать пропущенные проверки при `&&` и `||`, явно задавать порядок чтения и изменения состояния.

### Задание

Напиши программу в `main.go`, которая показывает порядок вызовов и помогает проверить прогнозы.

1. Объяви функции `traceInt(label string, value int) int` и `traceBool(label string, value bool) bool`. Каждая должна печатать только метку `label`, затем возвращать `value` без изменения.

2. Вычисли и выведи результаты двух выражений:

   ```go
   traceInt("base", 20) + traceInt("count", 3)*traceInt("unit", 4)
   (traceInt("base", 20) + traceInt("count", 3))*traceInt("unit", 4)
   ```

   До запуска запиши порядок меток и результат каждого выражения. Объясни, как скобки изменили расчёт.

3. В одном обычном цикле `for` обработай попытки от 1 до 3 включительно. Для каждой выведи номер и вычисли:

   ```go
   ready := traceBool("primary", attempt == 3) ||
       traceBool("backup", attempt == 2)

   allowed := traceBool("ready", ready) &&
       traceBool("quota", attempt == 3)
   ```

   Через `if` выведи `processed` либо `skipped`. Подсчитай и выведи после цикла количество обработанных попыток.

   До запуска запиши для каждой попытки порядок меток, какие вызовы будут пропущены, значения `ready` и `allowed`, а также итоговый счётчик.

4. Разбери фрагмент:

   ```go
   revision := 10
   advance := func() int {
       revision++
       return revision
   }
   total := revision + advance()
   ```

   В комментарии назови допустимые значения `total` и объясни, почему язык не гарантирует единственный результат. Затем измени расчёт так, чтобы гарантированно сложить прежнее значение `revision` с результатом одного вызова `advance`. Оставь в программе исправленный вариант и выведи `total` и итоговую `revision`.

### Ограничения и критерий

Используй числа, строки-метки, `bool`, функции, замыкание, `if`, числовой `for` и `fmt`. Коллекции, указатели, горутины, тесты и захват переменной цикла не нужны.

Критерий: прогноз сопоставлен с фактическим выводом; порядок вызовов отделён от группировки, пропуск проверок объяснён; исправленный расчёт явно задаёт момент чтения состояния. Цикл и ветвление работают, счётчик отражает фактически обработанные попытки.
