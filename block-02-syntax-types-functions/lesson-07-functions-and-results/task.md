## Practice — Batch Runner with Functions

Раздели знакомый алгоритм Batch Runner на функции: расчёт должен быть отделён от вывода, входные значения передаваться через параметры, а результаты возвращаться вызывающему коду.

### 1. Проверка номера

```go
shouldSkip(id, skipEvery int) bool
```

Функция возвращает, кратен ли `id` числу `skipEvery`. Она ничего не печатает.

Предусловия: `id >= 1` и `skipEvery > 0`. Проверку входов выполняет `runBatch` **до любых вызовов** `shouldSkip`.

### 2. Обработка пачки

```go
runBatch(total, skipEvery, maxProcessed int) (int, int, bool)
```

Функция возвращает `processed`, `idSum`, `ok` именно в этом порядке и ничего не печатает.

- Если выполняется хотя бы одно из условий `total < 0`, `skipEvery <= 0` или `maxProcessed <= 0`, сразу верни `0, 0, false` до цикла и вычисления остатка от деления. Здесь условия соединяются через «ИЛИ» (`||`).
- Иначе обходит номера от 1 до `total` включительно.
- Для отбора вызывает `shouldSkip` и пропускает номера, кратные `skipEvery`.
- Подсчитывает количество обработанных номеров и их сумму.
- Прекращает обработку сразу при достижении `maxProcessed`.
- После обычного завершения или достижения квоты возвращает итоги и `true`.
- `total == 0` — допустимая пустая пачка с результатом `0, 0, true`.

Выбери одну знакомую форму `for`.

### 3. Вывод отчёта

```go
printReport(label string, processed, idSum int, ok bool)
```

Это функция без результатов:

- при `ok == false` выводит `label` и сообщение `invalid input`, затем выходит через `return`;
- при `ok == true` выводит `label`, `processed` и `idSum`.

Точное оформление свободное, но отказ и корректные нулевые итоги должны однозначно различаться.

### 4. Связать функции в `main`

`main` задаёт входы, получает результаты `runBatch` и передаёт их в `printReport`. После **всех** отчётов один раз выводит `batch complete`.

В `main` не должно быть копии расчётного цикла. Внутри функций входы не подменяются константами.

Обязательные вызовы:

| `total` | `skipEvery` | `maxProcessed` | Ожидаемые `processed, idSum, ok` |
|---:|---:|---:|---|
| 8 | 3 | 4 | `4, 12, true` |
| 0 | 3 | 4 | `0, 0, true` |
| 8 | 0 | 4 | `0, 0, false` |

Последний вызов должен завершиться без деления на ноль; после него выполнение `main` продолжается. Достаточно трёх явных вызовов без коллекций и повторного написания алгоритма. Валидация должна охватывать все три запрещённых диапазона, хотя отдельный запуск нужен только для `skipEvery == 0`.

**Ограничения:** тела функций напиши самостоятельно. Можно смотреть свою практику 2.6 и использовать одну знакомую форму цикла. Не используй глобальные изменяемые переменные, указатели, коллекции, `range`, `error`, замыкания, variadic и автоматические тесты. Достаточно `int`, `bool`, `string`, обычных именованных функций и явного `return`.

**Критерий:** функции с одним, несколькими и без результатов написаны и связаны самостоятельно; порядок результатов и проверка входов корректны; три набора дают ожидаемый результат; пустая пачка отличается от отказа, а `main` продолжает работу. Также нужно объяснить передачу `int` по значению и путь `return`.
